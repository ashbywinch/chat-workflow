# Interview Notes — amp customer value & user-story flow

Notes from user interview / product thinking session.

> Why is this valuable to amp customers. They MIGHT like a PA. Mostly though they would like to be able to make playbooks for their common activities. So they don't have to write such detailed prompts. They want an architect who can guide them through architecture questions. They MIGHT want to make value streams and link that with their backlog gizmo. "Figuring out what to do next" sounds good. Full business planning is out of scope.
>
> Ultimately the outcome of the amp customer is "write code quickly"
>
> So they might need help getting a task refined. Figuring out what good looks like. If no tasks are groomed they need to make groomed tasks. Consider how we abstract the concepts of tactical planning from the notion implementation. We also need to give them the new employee workflow and make it auto detect. We SHOULD make them work in sessions. But they can wrap sessions ad hoc around tasks. They want to come in and architect and build a whole new thing asap.
>
> Ok we need a smaller milestone. An epic is plannable if the scope of work is reliably known and it's not going to creep. This one is unplannable.
>
> Features are called STORIES. First user story is, user can show up with a request like "I want to build this XYZ thing" and a software engineer will build it.
> 2. System detects that it's overcomplicated and they should design first. Ask the senior.
> 3. System detects that it's bigger than that and they should architect first. Ask the architect. Spitball common stories for an architect depending on which artifacts we need. This story is many stories.
> 4. Onboarding of engineer.
