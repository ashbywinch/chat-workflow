# Product Requirements Document — chat-workflow

## Requirements

### R1: Post-release user-driven evaluation

After release, a non-technical user must be able to systematically test and improve the system **according to their own definition of "good"**, rather than the definition of the vendor.

Prompt-eval tools focus on testing and improving a system *before* release; some tools help test and improve *after* release. Neither addresses the gap this requirement targets: enabling the end user — without technical expertise — to run their own evaluation loop and feed their own quality judgements back into the system.

### R2: Thinking-partner value proposition

The system is a **thinking partner**: it hides the underlying "organisation" from the user and helps them think intelligently about a problem, using a structured approach and standard brainstorming techniques. The result must be that **anybody can be a great prompt engineer** — no prompt-engineering expertise required on the user's part.

### R3: Executable operating model

The product is an **executable operating model for a business, made of AI prompts**, including an AI prompt designer that can create more prompts so as to grow the business. Two customer segments:

1. **Prompt-product sellers** — people wanting to sell products based primarily on AI prompts, needing a structured way to organise, develop and execute those prompts as if they were code.
2. **Business collaborators** — people wanting a product that collaborates with the user to create, run and grow a business with a mix of AI and human employees. Primarily solo entrepreneurs with only AI "employees" at first, but in theory any size of organisation.

The invention must present a **structured approach to constraining the actions of employees** (e.g. requiring sign-off from a human employee or external expert before proceeding). This is an essential part of AI-in-the-workplace governance and provides a structured way to understand and manage it.
